DBMS, RDBMS & Data Models

Moderate Asked in 5 of 9 papers · avg 8 marks

File processing vs DBMS, DBMS vs RDBMS, data models, data abstraction and independence, database administrator.

In your IGNOU bookBlock 2 · Unit 5 Business Information System (5.4 DBMS)

Key points

  • A DBMS is a collection of logically related data plus the operations needed to access it. A database system = database + DBMS.
  • Functions: define the structure and data types, add, update, delete and read data, keep it consistent, stop unauthorised access and allow recovery.
  • Limitations of file processing systems that a DBMS overcomes: data redundancy and inconsistency, data isolation, difficult access, integrity problems, concurrency problems and weak security.
  • Data models: record-based (hierarchical, network, relational) and object-based (entity–relationship, object-oriented). The relational model is the most widely used.
  • RDBMS stores data in tables (relations): row = tuple, column = attribute, schema = overall design, instance = the data at a given moment.
  • Data abstraction has three levels: physical (how data is stored), logical (what data is stored and how it relates) and external or view (what each user sees). Data independence lets one level change without affecting the next.
  • Database administrator (DBA): has overall control — designs the schema, grants access, handles backup and recovery.

Worked examples

Example: a relational table

Table STUDENT (the schema): Enrolment_No, Name, Course, City. Each row, such as (2301, Anu, BCom, Kochi), is a tuple; each column is an attribute. The rows stored today are the instance — they change as students join and leave; the schema does not.

Example: why a DBMS beats separate files

The fees office and the exam office each keep a file with the student's address. When a student moves, one file is updated and the other is not — redundancy leads to inconsistency. In a DBMS the address is stored once and both offices see the same data, with access controlled by the DBA.

Data independence: moving the database to a faster disk (physical level) does not change the tables users see.
